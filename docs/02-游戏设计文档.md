## 1. 概述

### 1.1 一句话描述

> 一款 2D 横板动作 Roguelike。玩家在不断重组的随机地牢中战斗，通过局内词条构筑与局外永久成长，逐步挑战更强的敌人与 Boss。

### 1.2 核心体验

📝 用 3 句话说明「玩家玩的时候感受到什么」。示例：

1. **操作爽快**：冲刺闪避、连击打击、命中顿帧，让每一次交锋都有反馈
2. **抉择焦虑**：「两个词条都想要，但只能拿一个」
3. **成长可见**：死在第 3 关，但解锁了新武器，下一局能走得更远

### 1.3 目标玩家

📝 喜欢《死亡细胞》《哈迪斯》《以撒的结合》的动作游戏玩家，单局时长 15–30 分钟。

## 2. 核心循环

这是整个设计里最重要的一张图。**如果这一节讲不清楚，游戏就没有设计。**

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
   ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌──────────┐
   │ 选择关卡 │───▶│ 战斗/探索│───▶│ 获得词条 │───▶│ 挑战 Boss │
   └─────────┘    └─────────┘    └─────────┘    └──────────┘
        ▲                                              │
        │                                              ▼
        │                                        ┌──────────┐
        │                                        │  死亡/通关 │
        │                                        └──────────┘
        │                                              │
        │              ┌──────────────┐                │
        └──────────────│ 局外永久解锁  │◀───────────────┘
                       └──────────────┘
```

### 2.1 局内循环（单局，15–30 分钟）

1. 从起点房间出发，面对 2–3 个出口
2. 每个出口通向不同类型的房间（战斗 / 精英 / 商店 / 宝箱 / Boss）
3. 清空房间获得货币与词条三选一
4. 玩家根据当前构筑决定下一间走哪
5. 击败 Boss 或死亡，本局结束

**⚙️ 设计要点**：出口类型要**可见**（门上显示图标）。玩家能规划路线，才叫「策略」；如果进门才知道是什么，那只是「赌博」。

### 2.2 局外循环（跨局，整个游戏周期）

1. 死亡后结算，获得「灵魂」（局外货币）
2. 在永久解锁界面消费：新武器、新词条进池、基础属性上限
3. 下一局以更强的初始状态开始，能走得更远
4. 回到局内循环

**⚙️ 设计要点**：局外成长必须是**横向解锁**（新东西进池）多于**纵向变强**（数字变大）。纯纵向会让游戏越玩越简单，失去挑战。

## 3. 玩法系统

### 3.1 角色动作

| 动作 | 设计说明 | 实现要点 |
| --- | --- | --- |
| 移动 | 有加速度，不是瞬间到最大速度 | 速度插值 / `MoveTowards` |
| 跳跃 | 支持二段跳 | 跳跃计数 + 重置条件 |
| 冲刺 | 带无敌帧，有冷却 | 冷却计时 + 期间忽略伤害 |
| 攻击 | 三段连击 | 连击窗口 + 输入缓冲 |

**手感细节（必做）**：

| 机制 | 作用 | 参考值 |
| --- | --- | --- |
| 土狼时间 | 离开平台后短时间内仍可跳 | 0.1 s |
| 跳跃缓冲 | 落地前按跳，落地自动起跳 | 0.1 s |
| 可变跳跃高度 | 松键削减上升速度 | 上升速度 ×0.5 |
| 下落重力加成 | 下落比上升快，手感更利落 | 上升重力的 1.5–2 倍 |
| 顿帧 Hitstop | 命中瞬间卡帧，强化打击感 | 0.05 s，`Time.timeScale = 0` |

### 3.2 战斗数值

| 属性 | 玩家基础值 | 说明 |
| --- | --- | --- |
| 生命值 | 📝 100 | |
| 攻击力 | 📝 10 | |
| 移动速度 | 📝 7 | 单位/秒 |
| 跳跃高度 | 📝 3.5 | 单位 |
| 冲刺冷却 | 📝 0.8 | 秒 |

📝 **伤害公式**（写清楚，答辩必问）：

```
最终伤害 = (基础攻击力 + 加算加成) × (1 + 百分比加成) × 暴击倍率 × 敌人减伤系数
```

> ⚠️ 注意加算与乘算的区别。「+10 攻击力」和「伤害 +10%」在数值成长曲线上完全不同，**先做加法、再做乘法**是让构筑产生质变的关键。

### 3.3 词条 / 遗物系统

**数据结构设计**：

```csharp
[CreateAssetMenu(menuName = "Roguelike/Relic")]
public class RelicData : ScriptableObject
{
    public string      displayName;
    [TextArea] public string description;
    public Sprite      icon;
    public Rarity      rarity;      // 普通 / 稀有 / 传说
    public RelicEffect effect;      // 多态：每个效果一个子类
}

public abstract class RelicEffect : ScriptableObject
{
    public abstract void Apply(PlayerStats stats);
}
```

📝 **词条表**（列出全部词条，标注稀有度与效果）：

| 名称 | 稀有度 | 效果 | 与其他词条的联动 |
| --- | --- | --- | --- |
| 锋利之刃 | 普通 | 攻击力 +5 | 与「暴击」类配合 |
| 迅捷护符 | 普通 | 攻速 +15% | 与「命中触发」类配合 |
| 📝 | | | |

**⚙️ 设计要点**：词条的价值在于**联动**。单个词条只是数值，两个词条组合产生新玩法才叫构筑。

### 3.4 关卡生成

**方案**：房间模板池 + 方向匹配拼接

```
1. 预先制作 8–12 个手工房间预制体，每个标记「入口方向 / 出口方向」
2. 从起点房开始，根据当前出口方向，从池中筛选「入口方向匹配」的房间
3. 按权重随机选取，拼接上去，直到达到目标房间数
4. 最后一个出口接 Boss 房
5. 全程使用同一个 System.Random(seed) 实例，保证可复现
```

**为什么不用纯算法生成**：算法生成的关卡容易「能走但难看」，而手工房间的质量上限高得多。《死亡细胞》用的就是类似的混合方案。

📝 **房间类型表**：

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| 起始房 | 1 | 无敌人，给玩家熟悉操作 |
| 普通战斗房 | 6 | 3–5 个敌人 |
| 精英房 | 2 | 1 个精英怪，掉落更好 |
| 商店房 | 1 | 用局内货币买词条/回血 |
| 宝箱房 | 1 | 免费词条 |
| Boss 房 | 1 | 关卡终点 |

### 3.5 敌人

📝 **敌人表**：

| 名称 | 类型 | 行为 | 血量 | 伤害 |
| --- | --- | --- | --- | --- |
| 巡逻兵 | 近战 | 巡逻 → 发现玩家 → 追击 → 近身攻击 | 📝 30 | 📝 10 |
| 弓手 | 远程 | 保持距离 → 射击 | 📝 20 | 📝 8 |
| 自爆虫 | 特殊 | 冲刺到玩家身边自爆 | 📝 15 | 📝 25 |
| 📝 精英 | 精英 | 普通怪 + 词条改造 | 📝 ×2.5 | 📝 ×1.5 |

**AI 设计**：三态状态机（`Patrol` / `Chase` / `Attack`）用 `enum` + `switch` 手写即可。**不要上行为树**——对这个规模是过度设计。

### 3.6 Boss

📝 **Boss 表**：

| 阶段 | 触发条件 | 技能 | 设计意图 |
| --- | --- | --- | --- |
| 阶段 1 | 血量 100%–50% | 冲刺撞击 / 横扫 | 教学：让玩家学会闪避时机 |
| 阶段 2 | 血量 <50% | 加入弹幕 / 召唤小怪 | 压力测试：检验构筑强度 |

### 4.2 音效

📝 来源同上。关键音效清单：跳跃 / 落地 / 攻击 / 命中 / 受击 / 死亡 / 拾取 / 升级 / Boss 出场。

### 4.3 打击感四件套

📝 这是「好玩」和「不好玩」的主要差别：

1. **顿帧**：命中瞬间时间暂停 0.05 s
2. **屏幕震动**：命中/受击时相机抖动
3. **粒子特效**：命中火花、死亡碎裂
4. **音效**：攻击声与命中声分离

## 5. 技术方案

### 5.1 架构分层

```
表现层  PlayerView / EnemyView        ← 动画、特效、音效
   ↓ 只读数据
逻辑层  PlayerController / EnemyAI    ← 状态机、输入处理
   ↓ 调用接口
系统层  DamageSystem / RelicSystem    ← 伤害计算、词条生效
   ↓
数据层  ScriptableObject 资产          ← 数值配置
```

📝 建议补充一张实际的架构图（`docs/images/architecture.png`）。

### 5.2 关键设计决策

📝 **答辩必问，提前想好答案**。示例：

| 决策 | 选择 | 理由 | 代价 |
| --- | --- | --- | --- |
| 关卡生成 | 房间池拼接 | 质量可控，实现周期短 | 需要手工做房间 |
| 词条系统 | ScriptableObject + 多态 | 加词条不用改代码 | 初次搭建成本高 |
| 敌人 AI | 手写状态机 | 简单直观，够用 | 敌人多了会重复 |
| 随机数 | 统一 `System.Random` + 种子 | 可复现，可写测试 | 需要传递 rng 实例 |
| 存档 | JSON | 可读，方便调试 | 需要手写序列化 |

### 5.3 数据存储

```
Application.persistentDataPath/save.json
{
  "version": 1,
  "unlockedWeapons": ["sword", "hammer"],
  "unlockedRelics": ["sharp_blade"],
  "souls": 350,
  "maxHealthLevel": 2
}
```

⚠️ **必须带 `version` 字段**。以后改存档结构时，靠它做兼容处理，否则老存档会直接崩溃。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 范围蔓延（想加太多系统） | 项目烂尾 | 严格执行 P0/P1/P2 优先级，每周五自检 |
| 美术资源找不到合适的 | 卡住进度 | 第 1–3 周一律用色块，第 4 周才换 |
| 关卡生成算法调不好 | 关卡难看 | 用房间池方案，必要时手工做 8 个房间兜底 |
| 打包版跑不起来 | 交不了作业 | 第 5 周周一就打包一次，别等最后一天 |
| 电脑故障 / 文件丢失 | 灾难 | 每周五 push 到 GitHub |
