# 五周排期

> 总工期：一个月 + 一周 = **5 周**。任务级清单见 [00-行动清单.md](00-行动清单.md)，本文只讲**每周该达到什么状态**。

---

## 时间预算（先算清楚）

假设每周投入 **15 小时**（工作日 1.5 小时 + 周末 6 小时），5 周共约 **75 小时**。

这 75 小时的分配建议：

| 用途 | 占比 | 小时 | 说明 |
| --- | --- | --- | --- |
| 核心玩法开发 | 45% | ~34 h | 移动、战斗、关卡生成、词条 |
| 打磨（美术/音效/UI/手感） | 20% | ~15 h | 决定「像不像完成品」 |
| 文档 / 报告 / PPT | 15% | ~11 h | **别等到最后一周，会撞车** |
| 调试与修 bug | 15% | ~11 h | 必然发生，预留出来 |
| 打包与发布 | 5% | ~4 h | |

**关键结论**：如果每周只有 5 小时，那就**必须**把阶段 3 的 P1 项全部砍掉，只保 P0。宁可做一个 5 分钟但完整好玩的循环，也不要做一个半成品的 30 分钟流程。

---

## 第 1 周：垂直切片

**本周目标**：一个房间、一个角色、一个敌人、能互相打死、能重开。**美术全是色块。**

| 交付物 | 验收标准 |
| --- | --- |
| 可运行的操作原型 | 室友拿到 `.exe` 能自己玩 30 秒不问你怎么操作 |
| Git 仓库 | GitHub 上有至少 10 次有意义的提交，`Library/` 没被提交 |
| 手感四件套 | 土狼时间 / 跳跃缓冲 / 可变跳跃高度 / 下落重力加成，全部生效 |

**本周最容易犯的错**：花 3 天找美术素材。
**怎么避免**：第 1 周统一用 Unity 自带的方块 Sprite，`Assets/_Project/Art/` 空着就行。

**周五必做**：打 tag `v0.1`，打包，自己完整玩 10 分钟。

---

## 第 2 周：肉鸽骨架

**本周目标**：一局游戏有完整的「开始 → 打几个房间 → 变强 → 打 Boss → 死或通关」循环。

| 交付物 | 验收标准 |
| --- | --- |
| 关卡生成 | 同一颗种子生成同一个关卡；连开 5 局，布局都不一样 |
| 局内进度 | 打完房间出现 2–3 个门通向不同类型房间 |
| 掉落词条 | 至少 8 个词条能实际生效，且能在 UI 上看到 |
| Boss | 有 2 个以上技能、血量过半会变招 |
| 数据驱动 | 新增一个词条**不需要改任何战斗代码** |

**本周最容易犯的错**：执着于「程序生成要够高级」，写出一个很炫但关卡很难看的算法。
**怎么避免**：用「手工房间池 + 随机拼接」。Dead Cells 就是这么做的。**手工房间的质量上限远高于算法生成。**

**周五必做**：打 tag `v0.2`。

---

## 第 3 周：构筑深度 + 局外成长

**本周目标**：让「策略」两个字成立——玩家要有取舍，而不是无脑变强。

| 交付物 | 验收标准 |
| --- | --- |
| 武器系统 | 3–5 把，手感差异明显（不是换个颜色和数字） |
| 词条联动 | 至少 3 组「1+1>2」的联动组合，能讲出原理 |
| 取舍决策 | 至少 3 处「两个都想要但只能选一个」的选择 |
| 局外成长 | 死掉后能用资源解锁新东西，并且下一局真的变强了 |
| 存档 | 关掉游戏重开，解锁进度还在 |

**本周最容易犯的错**：把词条做成「伤害 +5%」这种纯数值堆叠。
**怎么避免**：每个词条问自己一句「它会改变玩家的打法吗？」如果答案是「不会，只是数字变大了」，重做它。

> 这一周是决定作业是「及格」还是「优秀」的分水岭。**能不能让人产生「再来一局」的冲动，全看这周。**

**周五必做**：打 tag `v0.3`，找 3 个同学试玩，记录他们的原话。

---

## 第 4 周：打磨

**本周目标**：让它看起来不像课程作业。

| 交付物 | 验收标准 |
| --- | --- |
| 正式美术 | 角色/敌人/场景贴图替换完成，动画状态机跑通 |
| 打击感 | 命中时有粒子 + 音效 + 屏幕震动 + 顿帧 |
| 音频 | BGM 1–2 首，关键音效齐全（跳/打/受击/死亡/拾取） |
| 完整 UI | 主菜单 → 设置 → 暂停 → 死亡结算 → 再来一局，流程闭环 |
| 引导 | 前 30 秒玩家知道怎么操作 |

**本周最容易犯的错**：一边换美术一边改玩法，导致两边都没做完。
**怎么避免**：**第 4 周冻结玩法**。只允许改数值和资源，不允许加新系统。

**周五必做**：打 tag `v0.4`，录一段 60 秒演示视频（**这是简历最有用的资产**）。

---

## 第 5 周：交付

**本周目标**：所有交付物齐活，且都验证过。

| 交付物 | 验收标准 |
| --- | --- |
| 可运行包 | **换一台电脑跑一遍**，确认没问题 |
| README | 首屏有截图 + 下载链接，3 个 GIF |
| 设计文档 / 报告 | 能讲清楚设计决策和取舍，不只是罗列功能 |
| 答辩 PPT | 15–20 页，能讲 10 分钟 |
| 演示视频 | 60–90 秒，有解说字幕 |
| Release | GitHub 上有 `v1.0` tag 和打包 zip |

**本周最容易犯的错**：最后一天才发现打包版跑不起来（缺资源、分辨率不对、输入设备不识别）。
**怎么避免**：**周一就打包一次**，别等周五。

**周五必做**：打 tag `v1.0`，发布 Release，把链接贴到简历里。

---

## 落后了怎么砍

**判断标准**：每周五自检，如果本周验收标准没达到，立刻执行下面的砍法，**不要试图下周补回来**。

| 落后程度 | 砍什么 |
| --- | --- |
| 落后 1–2 天 | 砍阶段 3 的 P1 项（武器种类、词条数量砍半） |
| 落后 3–4 天 | 砍 Boss 二阶段；敌人种类砍到 3 种；局外成长只保留 1 条解锁线 |
| 落后 1 周 | 砍掉局外成长和商店，做「死 → 重开」的纯 Roguelike。**这仍然是一个完整游戏** |
| 落后 2 周 | 只保留 1 种敌人 + 1 个 Boss + 随机房间。**保住完整循环比保住内容量重要得多** |

**永远不要砍的**（砍了就不成立）：
1. 移动手感
2. 一局完整的「开始 → 结束」循环
3. README + 打包版
4. Git 提交历史
