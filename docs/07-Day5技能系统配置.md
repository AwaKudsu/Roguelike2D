## 2. 阶段 A：法师火球

做完这一阶段的效果：**法师按 K，往面朝方向飞出一颗橙色火球，砸中敌人扣 33 血。**

### A1. 给 Player 挂两个新组件

选中 Hierarchy 的 `Player` → `Add Component`：

| 组件 | 需要填的东西 |
|---|---|
| **Mana Pool** | 什么都不用填。数值从 `Character Stats` 读 |
| **Character Visual** | 什么都不用填。会自动找 `SpriteRenderer`。**现在看不出效果（方块翻不翻都一个样），但以后换贴图就靠它** |
| **Skill Caster** | 什么都不用填。依赖会自动找 |

**敌人也要挂一个 `Character Visual`**（选中敌人 → Add Component → Character Visual），不然以后换了贴图，敌人会倒着走向玩家。

两个组件下面都有 `Base Max Mana` / `Base Regen` / `Starting Skills` 之类的槽，**全部留空**——它们只是「职业资产没配」时的兜底。

> `Skill Caster` 的 `Log Failures` 先勾上。它会在技能放不出来时告诉你原因（蓝不够 / 冷却中 / 没配技能），验收完再关掉。

### A4. 做 `Fireball` 预制体

**第 1 步 · 在场景里搭一个临时火球**

Hierarchy 空白处右键 → `2D Object` → `Sprites` → `Square`
改名 `Fireball`（或 `Fireball_Temp`）。

**第 2 步 · 调外观**

| 组件 | 设置 |
|---|---|
| Transform | Position 随便（`0,0,0` 就行，反正要删）、**Scale `X 0.45` `Y 0.45` `Z 1`** |
| Sprite Renderer | **Color** 点开选一个橙色（R 255 / G 140 / B 40）、Sorting Layer 保持 Default |

**第 3 步 · 加刚体**

`Add Component` → `Rigidbody 2D`：

| 字段 | 值 |
|---|---|
| Body Type | **Kinematic** |
| Gravity Scale | `0` |
| Collision Detection | **Continuous** |

> 为什么是 Kinematic：投射物自己飞，不该被重力拽下去、也不该把敌人撞飞。Kinematic 不受任何力影响，但 `linearVelocity` 照样生效。

**第 4 步 · 加碰撞体**

`Add Component` → `Circle Collider 2D`：

| 字段 | 值 |
|---|---|
| Radius | **0.5** |
| **Is Trigger** | **✅ 勾上** |

> Radius 填 0.5 而不是 0.2：**碰撞体半径是「本地坐标」，会跟着 Scale 一起缩放**。0.5 × 0.45 = 世界半径 0.225，正好把 0.45 大小的方块包住。

**第 5 步 · 加 Projectile 脚本**

`Add Component` → `Projectile`：

| 字段 | 值 |
|---|---|
| Speed | **14** |
| Life Time | **1.2** |
| Target Layers | 留空（会被 AttackData 覆盖） |
| **Obstacle Layers** | **只勾 `Ground`** ⚠️ |
| Pierce | 不勾 |
| Max Hits | `0` |
| Rotate To Direction | 不勾 |
| Destroy Delay | `0` |

> 填完 `Obstacle Layers` 之前，Console 会有一条黄色警告 `[Projectile]「Fireball」的 Obstacle Layers 是空的…`。勾上 `Ground` 后警告消失。**这条警告是故意留的**，专治「火球穿墙飞出去还查不出原因」。

**第 6 步 · 存成预制体**

把 Hierarchy 里的 `Fireball` **拖到** Project 面板的 `Assets/_Project/Prefabs/` 里。

> 如果 `Prefabs` 下想再分类，先建 `Assets/_Project/Prefabs/Projectiles/`，拖进去。

**第 7 步 · 删掉场景里的那个**

Hierarchy 里右键 `Fireball` → `Delete`。场景里不需要它，它现在是 Project 里的资产了。

**第 8 步 · 把预制体接上**

- 打开 `Attack_Fireball` → `Projectile Prefab` 槽 ← 拖 `Fireball` 进去
- 打开 `Skill_Fireball` → `Projectile Prefab` 槽 ← 拖 `Fireball` 进去

> **两个都要拖。** `Attack_Fireball` 的是给「远程普通攻击」用的，`Skill_Fireball` 的是给技能用的。现在看起来重复，但阶段 C 它们会指向不同的预制体。

### A5. 更新 `Class_Mage`

Project 面板双击 `Assets/_Project/Data/classes/Class_Mage.asset`，在已有数值下面补三行：

| 字段 | 原值 | 改成 |
|---|---|---|
| Max Mana | （默认 100） | **100** |
| Mana Regen | （默认 6） | **5** |
| **Starting Skills** | 空 | `Size` 填 **1**，把 `Skill_Fireball` 拖进 `Element 0` |

其余保持不变：Max Health 85 / Attack 11 / Move Speed 7.5 / Attack Speed 1.4 / Crit Chance 0.15 / Crit Multiplier 1.8 / Defense 0 / **Basic Attack 暂时仍指 `Attack_Basic`**（阶段 C 再换）。

> 数值意图：火球 12 蓝 / 1.5 秒 = 每秒 8 点消耗，而回蓝只有每秒 5 点。**法师不能站着无限放火球**，必须穿插普攻等回蓝——这正是两个职业手感不同的来源。

### A6. 验收（阶段 A）

1. 选中 `Player`，把 `Character Stats` 的 **Class Data** 设为 `Class_Mage`（如果还不是）
2. 确认场景里有一个敌人（Day 4 做的那个紫色方块）
3. 按 **Play**
4. 按 **K**

| 应该发生 | 如果没发生 |
|---|---|
| Console 无报错 | 看 Console 红字 |
| 角色朝哪边，火球就往哪边飞 | 火球不动 → `Skill Caster` 的 `Log Failures` 没勾，勾上看提示 |
| 火球飞 1.2 秒后自己消失 | 一直飞 → `Life Time` 没填 |
| 火球穿过地面继续飞 | `Obstacle Layers` 没勾 `Ground` |
| 火球穿过敌人 | `Attack_Fireball` 的 `Target Layers` 没勾 `Enemy` |
| 打中敌人 → 敌人闪白 + 掉血 + 被推开 | 掉血了但不闪白 → 敌人身上没有 `Hit Reaction` |
| **看 Inspector 的 Mana Pool，蓝条掉 12** | 蓝没掉 → `Skill_Fireball` 的 `Mana Cost` 是 0 |
| 连按 K，第二次没反应 | ✅ 正常，1.5 秒冷却 |
| 等 1.5 秒后再按，又能放 | ✅ 正常 |

5. 打开 Inspector 观察 `Mana Pool` 的 `Current`：放完火球后它会停 0.6 秒不回复，然后慢慢涨回 100

**阶段 A 通过 → 继续。没通过 → 先修好再往下，后面建立在它之上。**

## 3. 阶段 B：战士旋风斩

效果：**战士按 K，原地转一圈，身前身后 3.2 × 2.2 范围内的敌人都挨 45 点伤害并被击退。**

### B1. 新建 `Attack_Whirlwind`

`Assets/_Project/Data/Weapons/` → 右键 → `Create` → `Roguelike` → `Attack Data` → 改名 `Attack_Whirlwind`

| 字段 | 值 | 说明 |
|---|---|---|
| Display Name | `旋风斩` | |
| Damage Multiplier | **3.5** | 战士 13 攻 × 3.5 = 45.5 |
| Knockback Force | **14** | 比普攻（默认值）更狠，打散怪群 |
| Bonus Crit Chance | `0.1` | +10% 暴击，让大招更有爆发感 |
| **Hitbox Offset** | **`X 0` `Y 0`** | ⚠️⚠️ **本节最容易被漏的一格**：新建的资产默认是 `X 0.8`（判定框挪到身前）。它长得像「本来就对的默认值」，所以极容易跳过不填。**必须手动改成 0** |
| **Hitbox Size** | **`X 3.2` `Y 2.2`** | 比普攻大得多 |
| **Target Layers** | **只勾 `Enemy`** | |
| Is Ranged | **不勾** | |
| Projectile Prefab | 留空 | |
| Cooldown | `0.35` | 会被技能资产覆盖，随便填 |

> **这一个数值就是旋风斩的灵魂**：普通攻击 `Attack_Basic` 的 `Hitbox Offset` 是 `X 0.8`，判定框只在身前。把偏移改成 0，同一个判定代码立刻变成「原地转圈」。这就是 Day 5 把 `PlayerAttacker.Execute()` 抽成 public 的回报——技能不需要重写一遍打人逻辑。
>
> **为什么必须强调它**：`AttackData.hitboxOffset` 的 C# 默认值曾经是 `Vector2(0.8f, 0f)`。新建资产时 Unity 就按这个默认值填进去，你看到 `0.8` 会以为「这是默认的，应该没错」，于是跳过这一格。结果是：判定框中心偏到身前 0.8，宽 3.2 的话覆盖 `[-0.8, +2.4]`——**身后的敌人只要站在 0.8 以外就打不到**。而敌人正好会停在离你 1.3 的位置。于是症状是「旋风斩只有身前判定」，看起来像代码 bug，实际是一个被默认值掩盖的填表遗漏。
>
> 现在 `AttackData.cs` 的默认值已经改成 `Vector2.zero`（居中），新建的攻击资产默认就是对称的。但**已经建好的 `Attack_Whirlwind` 不受影响**——它的值序列化在 `.asset` 文件里，得手动改。宁可错得明显（打到太多，一眼看出），也不要错得安静（打不到，看起来像玄学）。

### B4. 验收（阶段 B）

**第 0 步：确认判定框闪示是开着的（这是本节的验收工具，别跳过）**

选中 Hierarchy 里的 `Player` → Inspector 里 `Player Attacker` 组件 → 确认 **`Debug Show Hitbox`** 是勾上的（默认就是勾上的）。

它的行为是：**按下攻击 / 技能的那一刻，在 Scene 视图闪出一个判定框，`Debug Show Duration` 秒之后自动消失。** 平时不画任何东西。

| 颜色 | 是什么 |
|---|---|
| **亮黄色框** | **普通攻击**打出去的那一下（按 J） |
| **亮青色框** | **技能**打出去的那一下（按 K，比如旋风斩） |

框画在**你按下按键那一刻实际结算的位置**，前后左右对称不对称，一眼就能看出来。默认闪 **0.6 秒**——如果你还是来不及切到 Scene 视图，把 `Debug Show Duration` 调到 `1.5` 或 `2`，验收完再调回来。

> 💡 **想看得更从容**：按下去之后立刻点 Unity 工具栏的 **暂停（⏸）**。暂停时 `Time.time` 不再走，闪框会**一直停在那里**，你可以慢慢量。看完再点一下继续。

> ⚠️ **不要去找「常驻的暗红色框」了。** 早先的版本画过一个永久显示、跟着角色走的框，用来预览「现在打会打在哪」——那个已经删掉了。现在只有按下去才闪，闪完就没。

1. 选中 `Player`，`Character Stats` 的 **Class Data** 改成 `Class_Warrior`
2. 按 Play，**先站着不动按一下 K**
3. **看 Scene 视图里闪出来的亮青色框：它应该以角色为中心、左右对称。** 如果它明显偏向你面朝的那一侧（偏出去约 0.8 格），说明 `Hitbox Offset` 不是 0 —— 回到 B1 改
4. 站到敌人旁边，**注意要走到敌人身前，让另一个敌人也在你身后一格的范围内测试**
5. 按 **K**

| 应该发生 | 说明 |
|---|---|
| 按下 K 的瞬间，Scene 视图闪出一个大大的亮青色框，约 0.6 秒后消失 | 不需要选中 Player 也会画 |
| **身后的敌人也被打到** | 这是本阶段最核心的验收点 |
| 敌人被推得比普攻远 | `Knockback Force 14` 生效 |
| 蓝条一次掉 20 | |
| 4 秒内再按 K 没反应 | 冷却生效 |

4. **换职业测试**：把 `Class Data` 从 `Class_Warrior` 切成 `Class_Mage` 再切回来，确认技能栏会跟着换（`Skill Caster` 订阅了 `ClassChanged` 事件）

> ⚠️ **换职业要在 Play 模式外改，或者改完重新 Play。** 在 Play 模式里改 Inspector 的值，停止后会全部回滚——这是 Unity 的规则，不是 bug。

### C4. 验收（阶段 C）

### 6.1 头号嫌疑犯：`Simulated` 被取消了勾选

**症状组合**：火球**既不动、又穿过敌人**。两个症状同时出现，几乎一定是这一个原因。

`Rigidbody 2D` 组件里有一个 `Simulated`（模拟的）复选框。它的意思是「这个刚体要不要参与物理世界」。

取消勾选之后：

- `linearVelocity` / `AddForce` 全部**无效** → 火球不会动
- 这个刚体**完全不产生任何碰撞和触发回调** → `OnTriggerEnter2D` 永远不执行 → 火球穿过敌人、穿过地面、什么都不碰

一个开关，两个症状。

**为什么会被误取消**：在 Inspector 里，`Simulated` 就在 `Body Type` 的**正下方**，而配置步骤要求你依次改 `Body Type`、`Gravity Scale`、`Collision Detection` —— 都在同一列里点。它看起来像个无害的小勾，很容易顺手点掉。

**怎么修**：Project 面板双击 `Fireball` 预制体 → Inspector 里 `Rigidbody 2D` → 把 `Simulated` 勾回来 → `Ctrl+S`。

**怎么预防**：以后凡是复制 `Rigidbody 2D` 组件（右键 `Copy Component` → `Paste Component As New`），**第一件事就是检查 `Simulated` 有没有跟着被复制**。

**顺带一提，剩下的 `Simulated = false` 从哪来的**：`Projectile.cs` 的 `Expire()` 里有一句 `_rb.simulated = false;`，那是投射物命中或超时后主动「关掉自己」用的。如果预制体是在 Play 模式里从已经失效的火球身上存下来的，就会带上这个值。**这也是为什么调参要在停止 Play 之后做** —— 见上面表格倒数第二行。

### 6.2 第二号嫌疑犯：默认值看起来总是「对的」

**症状**：旋风斩按下去有反应、有冷却、有伤害数字，**但只打得到身前的敌人**。身后的敌人纹丝不动，Console 干干净净。

**算一遍就明白了**。`AttackData.hitboxOffset` 新建时的默认值是 `X 0.8`，于是：

```
判定框中心 = 角色位置 + (0.8 × 朝向, 0)

面朝右：中心在 +0.8，宽 3.2 → 覆盖 [-0.8, +2.4]
面朝左：中心在 -0.8，宽 3.2 → 覆盖 [-2.4, +0.8]
```

而 `EnemyController.attackRange` 是 **1.3** —— 敌人追到你身边就会停在 1.3 的位置。

- 敌人在**身前**（+1.3）：落在 `[-0.8, +2.4]` 里 → **打得到**
- 你转身后它在**身后**（还是 +1.3）：`+1.3 > +0.8`，**差 0.5** → **打不到**

所以「旋风斩只有身前判定」不是判定逻辑的问题，是**判定框中心偏了 0.8**。

**这个坑为什么难发现**：`0.8` 是新建资产时 Unity 自动填的，你打开 Inspector 看到它，很自然会想「这是默认值，应该没错」——**而它长得和「正确的值」一模一样**。

**根治办法（已经做了）**：`AttackData.cs` 的默认值改成了 `Vector2.zero`（居中）。原则是——

> **宁可错得明显，也不要错得安静。**

默认居中时，如果忘了改，攻击会**打到太多**（身后怎么也挨打？一眼看出不对）。默认身前时，如果忘了改，攻击会**打不到身后**——技能照样能命中，于是错误永远不暴露，直到你花两小时怀疑代码。

**以后新建任何攻击资产，养成这个习惯**：填完数值，**先按一下，再切到 Scene 视图看闪出来的框**（普攻亮黄色、技能亮青色）。框在哪，判定就在哪。这是唯一能让你「看见」数据的方法，比读一遍表格可靠。

## 9. 以后换成真正的贴图怎么办

现在角色是正方形。**这不是凑合，是故意先把逻辑跑通。** 换贴图的时候你会发现代码一行都不用改——因为没有任何一行代码引用「Square」这个东西，贴图存在 `SpriteRenderer.sprite` 里，换掉就行。`HitReaction` 用的是 `GetComponentInChildren<SpriteRenderer>()`，`CharacterVisual` 也是，它们不关心贴图长什么样。

但**有 5 个地方会咬人**，现在提前讲清楚。

### 9.1 头号杀手：贴图轴心（Pivot）

现在方块贴图的轴心是 **Center**，碰撞体 `Offset (0,0)`、`Size (1,1)`——三者是自洽的：`transform.position` 在身体正中央，脚底在 `-0.5`。

换成人物立绘时，**轴心和碰撞体必须一起改，不能只改一个**。两个自洽方案，选一个：

| | 方案一：保持 Center | 方案二：Bottom Center（推荐） |
|---|---|---|
| 贴图轴心 | Center | **Bottom Center** |
| 碰撞体 Offset | `(0, 0)` | **`(0, 0.5)`** |
| 碰撞体 Size | `(0.6, 1)` | `(0.6, 1)` |
| `transform.position` 代表 | 身体中心 | **脚底** |
| 缺点 | 做下蹲 / 跳跃动画时，每帧人物在贴图里的位置会变，角色会上下抖 | 需要改碰撞体 |
| 好处 | 什么都不用动 | **脚是锚点，动画不会抖**；关卡设计师看坐标就知道站多高 |

**推荐方案二**，因为等你要做跳跃、下蹲、受击这些动画时，方案一的抖动会让你抓狂，而那时候再改，所有关卡摆位都要重调。

改轴心的位置：选中 PNG → Inspector 里点 **`Sprite Editor`** → 左下角 `Pivot` 下拉选 `Bottom Center` → `Apply`。

### 9.2 Pixels Per Unit：决定人物多大

现在方块是 Unity 内置 sprite，PPU = 100。

**目标：让「人物的世界高度 ≈ 1 单位」。** 因为现在所有数值都是按 1 单位高的身体调的。

| 贴图里人物高 | PPU 应该填 |
|---|---|
| 32 像素 | **32** |
| 48 像素 | **48** |
| 16 像素 | 16 |

> **PPU 就是「多少像素 = 1 个 Unity 单位」。** 32 像素高的人物、PPU 填 32 → 世界高度正好 1.0 单位，和现在的方块一样大，**攻击判定框、跳跃力度、地面间距全都不用动**。
>
> 如果 PPU 填错成 100，32 像素的角色只有 0.32 单位高，比现在小三倍——判定框全部打空，摄像机看着像在天上。

**所有素材用同一个 PPU。** 一个包一个 PPU，不要一包一个。

### 9.3 碰撞体要比贴图窄

美术通常比「身体」宽：挥剑的手臂、飘起来的斗篷、头盔上的角。

**碰撞体只包躯干**，宽 0.5~0.6、高 1 就够。碰撞体跟着贴图走的话，角色会卡在墙前面半米过不去。

保持 **`Capsule Collider 2D` + `Direction = Vertical`**，理由和 Day 1 一样：胶囊的圆弧底不会被地面碰撞体的接缝卡住，而且头顶的圆弧会让角色能滚上一格小台阶——那是你想要的手感。

### 9.4 贴图导入设置

选中 PNG，Inspector 里设：

| 设置 | 像素风 | 手绘风 |
|---|---|---|
| Texture Type | `Sprite (2D and UI)` | 同 |
| Sprite Mode | `Single`（单张）/ `Multiple`（图集，用 Sprite Editor 切） | 同 |
| **Pixels Per Unit** | 见 9.2 | 见 9.2 |
| **Filter Mode** | **`Point (no filter)`** | `Bilinear` |
| **Compression** | **`None`** | `Normal Quality` |
| Generate Mip Maps | **取消勾选** | 取消勾选 |
| Alpha Is Transparency | ✅ | ✅ |
| Wrap Mode | `Clamp` | `Clamp` |

> **像素风必须 `Point` + `None`。** 用默认的 `Bilinear` 会让像素边缘糊成一团，用默认压缩会出彩色噪点——而且这两个问题在 Game 视图缩小看的时候**看不出来**，等你全屏播放才发现，那时候会以为是摄像机的问题。

**每个 PNG 都要单独设。** 导入设置是记在 `.meta` 上的，不是全局的。所以 `.meta` 一定要提交。

### 9.5 排序层：现在就该加

`Edit → Project Settings → Tags and Layers` → 最下面的 **Sorting Layers**，加 4 层（Unity 里越靠下的**越后画 = 越靠前**）：

```
Background
Ground
Characters
Foreground
```

然后：地面 `Sprite Renderer` 的 `Sorting Layer` 设 `Ground`，Player 和敌人设 `Characters`。

**Player 的 `Order in Layer` 设成 10**，敌人保持 0——这样玩家和敌人重叠时玩家永远在前面，不会闪。

> **为什么现在就该加**：现在所有东西都是 `Default` / `Order 0`，排序只靠 z 坐标，而它们 z 全是 0。两块不透明方块重叠你看不出来，但**两块带透明边缘的贴图完全重叠时，谁前谁后是未定义的，会帧帧闪烁**。等看到闪烁再回头查，你会先怀疑渲染管线、怀疑 Shader，最后一个才会怀疑排序层。

### 9.6 数值重调：只要人物是 1 单位高，就不用调

这些数值单位都是**世界单位**，是按 1 单位高的身体调的：

| 位置 | 值 | 什么时候要改 |
|---|---|---|
| `Attack_Basic` 的 `Hitbox Offset` | `(0.8, 0)` | 人物变宽/变高时 |
| `Attack_Whirlwind` 的 `Hitbox Size` | `(3.2, 2.2)` | 同上 |
| `ProjectileLauncher.MuzzlePosition` 的 `forwardOffset` | `0.55` | 发射点跑到身体里或离身体太远时 |
| `PlayerController` 的 `jumpForce` | `13` | 人物变高后，同样的跳跃高度看起来变矮了 |

**结论：只要把 PPU 设对、让人物保持 1 单位高，上面这些一个都不用动。** 这就是 9.2 强调 PPU 的意义。

### 9.7 朝向翻转已经解决了

`CharacterVisual` 这个组件今天已经加进项目、也接好了线。给 Player 和敌人都挂上，以后贴图朝哪边就自动正确。

不挂也不会报错（代码里全是 `_visual != null` 判空），只是人物会永远朝右——**问题在于你不会立刻发现**：方块朝哪边都一样，等换了贴图才暴露。所以趁现在挂上。

### 9.8 素材从哪来

项目里已经有一份现成的指南：`Assets/ThirdParty/SOURCE.md`。里面有：

- 6 个免费素材站 + 各自的协议
- **协议避坑表**（CC0 / CC-BY / CC-BY-SA / CC-NC / GPL 各能不能用）
- 素材登记模板

**老师会问「美术哪来的」，面试官也会问。** 能答出「Kenney，CC0，无需署名」是专业素养；答「网上找的」是风险。每引一个包，就在 `ThirdParty/<包名>/` 下写一份 `SOURCE.md`。

推荐顺序：

| 素材包 | 协议 | 适合 |
|---|---|---|
| **Kenney**（kenney.nl） | CC0 | 首选，量大、省事、无需署名 |
| itch.io 上 LuizMelo 的 *Hero Knight* / *Martial Hero* / *Huntress* | 免费 | **像素风、带完整动画（待机/跑/跳/攻击/受击/死亡），和本项目的动作肉鸽最搭** |
| Kenney 或 itch.io 上的 *Sunny Land* / *Pixel Adventure* | CC0 / 免费 | 带完整地形 tileset |

> ⚠️ **人物和敌人的美术必须来自同一套素材包。** 混用的结果是一个八头身小人追着一个二头身怪物——哪怕配色协调，一眼也能看出是拼的。地形 tileset 混用问题不大（都是方形地块），**角色不行**。
>
> 如果一套包里没有合适的怪物，就在同一套包里找能改色的（很多包会把同一个怪物出成红/蓝/绿三色），或者用 Sprite Renderer 的 `Color` 调色——**这也是为什么现在敌人是暗紫色方块还能用**。

### 9.9 换贴图的操作清单

到时候照着做，不用重新想：

1. PNG 拖进 `Assets/ThirdParty/<素材包名>/`，同时在那个目录写 `SOURCE.md`
2. 选中 PNG → 按 9.4 的表格设导入设置 → `Apply`
3. 选中 Sprite 资产 → `Sprite Editor` → `Pivot` 设 `Bottom Center` → `Apply`
4. 选中 Player → `Sprite Renderer` 的 `Sprite` 槽 ← 拖贴图进去
5. 改 `Capsule Collider 2D` 的 `Offset` / `Size`（按 9.1 选定的方案）
6. 设 `Sorting Layer = Characters`、`Order in Layer = 10`
7. 确认 Player 上有 `Character Visual` 组件
8. 敌人重复 2 / 5 / 6 / 7 步（`Order in Layer` 留 0）
9. 加 Sorting Layers（只需做一次）
10. Play 验收一遍：能走能跳能打、贴图不抖、不闪、能滚上台阶

> PNG 已经被 Git LFS 追踪了（脚手架阶段配好的），直接 `git add` 就行，不用担心仓库变大。

### 9.10 动画是下一步，不是今天的事

以后加 `Animator` 时，`PlayerController` 需要暴露两个只读属性给动画状态机：

```csharp
public float HorizontalSpeed => Mathf.Abs(_rb.linearVelocity.x);
public bool  IsGrounded      => _isGrounded;
```

然后 Animator 里按 `HorizontalSpeed` 和 `IsGrounded` 切换 待机 / 跑 / 跳 / 落 四个状态。**现在不用加**，先把贴图换上去，动画是最后一步的打磨。
